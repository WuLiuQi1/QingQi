# 01 · 产品与 UI 设计

## 1. 产品定义

暂定名：**轻启 / QingQi**。名称尚未做商标、重名或 App Store 可用性检索。

核心主张：**少一点广告，多一点直接。**

实际产品描述：通过用户授权的系统 URL 过滤，减少可识别的联网广告请求。不会自动点击其他 App，不保证所有开屏广告、素材缓存或倒计时都消失。

目标用户：普通未越狱 iPhone 用户。首版生产功能以 iOS 26+ 为基线。[S2][S4]  
商业优先级：先验证有效性、误拦截和成本，再考虑收费。V1 不放广告、不要求账号、不做社交、积分和排行榜。

## 2. 第一版只做什么

### 核心能力
1. 系统过滤配置的安装/启用引导、状态回读和关闭。
2. 一个固定的“基础广告规则”配置档，不开放任意规则组合。
3. 规则版本、来源、类别、验证信息和更新状态展示。
4. 用户主动运行的受控自检。
5. 本地配置事件记录、问题反馈草稿和隐私说明。

URL Filter 自动覆盖使用 WebKit / URLSession 的请求；其他网络实现需要对方主动接入参与 API，因此不是任意 App 任意协议的全覆盖。[S3][S5]

### 暂缓能力
个人例外、自定义订阅、按 App 开关、拦截统计、自动恢复定时器、付费、云同步均不属于 V1 必交功能。

“按 App 看兼容性”只是一份人工测试说明，不等于运行时能识别请求来自哪个 App。规则一旦进入全局配置，可能影响多个 App；界面必须说明。

## 3. 信息架构

底部原生 TabView，共四项：

| 页面 | SF Symbol | 核心问题 |
| --- | --- | --- |
| 概览 | leaf | 现在启用了什么？怎样关闭？ |
| 规则 | line.3.horizontal.decrease.circle | 当前规则是什么，依据是什么？ |
| 诊断 | stethoscope | 当前配置能否正常工作，出了问题怎么办？ |
| 设置 | gearshape | 数据如何处理，如何管理配置？ |

不设置“统计”标签，不暗示有系统 API 未提供的全设备可观察性。

## 4. 概览

### 布局
顶部：产品名、简短说明。  
第一屏核心：大状态卡，图标 + 精确状态 + 解释 + 一个主按钮。  
第二组：已应用规则版本、最近受控自检结果。  
底部：生效范围说明、去诊断的入口。

### 状态不是单一布尔值

| 内部状态 | 显示文案 | 主要操作 |
| --- | --- | --- |
| notConfigured | 尚未配置 | 设置过滤 |
| requestingAuthorization | 正在准备配置 | 按钮禁用，允许取消尚未提交的操作 |
| requiresApproval | 等待系统确认 | 查看启用指引 / 重新检查 |
| configuredEnabled | 配置已启用 | 关闭过滤 |
| configuredDisabled | 过滤已关闭 | 重新启用 |
| degraded | 自检发现异常 | 查看诊断 / 关闭过滤 |
| unsupported | 当前系统不支持 | 查看系统要求 |

`configuredEnabled` 只表示从系统回读到配置已启用，不等于每条请求经过过滤，也不等于服务器健康。不得改写成“全面保护”“所有广告已拦截”。

“已应用规则版本”必须来自实际生效版本证据；仅下载成功显示“已下载，等待应用”。原型中的版本全部加“示例”。

### 授权流程
使用说明 → 调用正式配置 API → 系统真实授权过程 → 用户返回 → 重新读取系统配置 → 更新 UI。[S4]  
不要用自绘弹窗替代实际系统授权。浏览器和 SwiftUI 原型只能模拟，必须显示“不会安装系统配置”。

### 关闭体验
关闭不藏进付费墙。调用真实关闭动作后回读验证；失败时保留原状态并显示原因。  
V1 不提供“10 分钟后自动恢复”：没有经过验证的系统调度保障前，后台计时不能作为可靠承诺。

## 5. 规则页面

默认展示“基础广告规则”，不做“强力 / 极速 / 百分百”等模式。

规则卡字段：
- 名称、用途、是否默认启用。
- 下载版本与应用版本。
- 规则规模（实际产物数，不是拦截次数）。
- 最近校验时间、来源与授权信息。
- 已知影响与回退说明。

规则详情使用三段：匹配对象、验证依据、可能影响。  
所有示例规则用 example 保留域名；测试对象和成功率不得编造。

V1 规则分类用于说明，不必做成可以随意切换的独立引擎配置：
- 独立广告服务域名。
- 经过验证的 URL 组成项。
- 误拦截修复记录。

搜索仅搜索规则元数据，不搜索用户的网络访问历史。

异常规则反馈：“报告误拦截”。不提供尚未实现的“一键对此 App 放行”。临时恢复联网的可用手段是关闭过滤，再反馈。

## 6. 诊断页面

自检由用户主动触发。不扫描安装的 App，不自动抓取最近访问的域名。

检查项：
1. 系统版本与过滤配置。
2. 实际应用的规则版本。
3. 受控允许资源的可访问性。
4. 受控阻止资源的结果。
5. 规则服务与 PIR 路径的健康状况（只在可测范围内）。

状态：未检查、检查中、通过、失败、无法判断。  
“请求失败”不自动等于“成功拦截”。DNS 故障、断网、服务器异常和正常拦截需分开；没有足够证据时显示“无法判断”。

自检页面只报告测试请求，不显示伪造的全设备网络日志。配置事件可记录“用户开始配置”“应用规则 vX”“用户关闭过滤”，不记录浏览历史。

反馈草稿字段：
- 用户手工填写的 App 名称和版本（可选）。
- 问题类别：广告仍出现 / 正常页面异常 / 无法启用 / 其他。
- 规则版本、iOS 版本、用户勾选的诊断摘要。
- 自由描述；提示用户勿填写账号、验证码等敏感信息。
- 提交前完整预览，可取消。

## 7. 设置页面

“外观”：跟随系统 / 浅色 / 深色。  
“隐私”：数据处理说明、诊断数据默认不上报、清理本地配置事件。  
“帮助”：覆盖范围、误拦截恢复步骤、第三方规则授权。  
“系统配置”：查看操作指引、关闭/移除配置（实现后需回读结果）。  
“关于”：版本、条款、隐私政策、联系渠道。

不承诺“无任何服务器接触”。PIR 查询、CDN 更新仍有服务端通信；准确披露其用途及采用的隐私机制。[S3]

## 8. 视觉系统

设计方向：安静、可信、轻量。不是传统 VPN 的节点测速面板，也不是杀毒软件的危险警报面板。

### 颜色
| Token | 浅色 | 深色 |
| --- | --- | --- |
| background | #F4F6F3 | #101916 |
| surface | #FFFFFF | #1A2722 |
| textPrimary | #16352D | #F0F7F2 |
| textSecondary | #5B7067 | #AFC2B8 |
| accent | #086F5A | #83D9B6 |
| accentSoft | #E5F2EB | #203E32 |
| separator | #DEE7E1 | #32473C |
| warning | #8C5705 | #F0C279 |
| danger | #B33B35 | #FFB5A8 |

深色主按钮使用浅绿色底和深色文字，不沿用白字。对比度由实现阶段工具检查；不能仅靠颜色区分状态。

### 尺寸与字体
系统字体，不捆绑字体文件。标题 30–34 pt bold，分组标题 19–22 pt semibold，正文 16–17 pt，辅助说明优先 13–14 pt。支持 Dynamic Type。

页面水平边距 20 pt，8 pt 间距基准，卡片圆角 22–28 pt。主要按钮至少 52 pt 高，其余交互目标至少 44×44 pt。内容允许换行，不锁定卡片高度。

### 组件
StatusHero / StateBadge / PrimaryButton / RulePackCard / InfoRow / DiagnosticRow / EmptyState / InlineNotice。

底部使用原生 TabView；主体不自绘系统键盘、权限弹窗和返回按钮。视觉稿是设计参考，生产 UI 应遵循系统行为。

### 动效与无障碍
短状态过渡，不使用常驻旋转或循环呼吸动画。尊重 Reduce Motion。  
VoiceOver 读出完整状态；图标没有独立信息时隐藏其辅助功能元素。  
屏幕阅读顺序：标题 → 状态 → 主操作 → 配置详情 → 辅助说明。  
支持较大字体、小屏幕、深色、横屏，核心操作不得溢出或被键盘遮挡。

## 9. 原型与生产的区别

本包 HTML 与 SwiftUI 为离线演示。配置、规则、诊断都是示例，不会拦截任何广告。  
所有演示视图必须保留“演示模式”提示。生产版本不得把相同假数据接入真实状态页面。  
`MockFilterEngine` 只用于 Preview / Debug；Release target 中应由编译与依赖注入保证无法误用。

## 10. 产品验收

成功标准不是“用户觉得开关亮了”，而是：
- 用户知道功能覆盖范围与限制。
- 状态可回读，关闭可验证。
- 能证明在目标样例上有效，且没有关键业务误拦截。
- 后端有可测的成本模型。
- 页面不展示编造的统计、设备信息或兼容性结论。
