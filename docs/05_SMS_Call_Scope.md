# V2 范围决策：短信过滤 + 来电过滤

## 当前主线

### 短信过滤

使用 Apple IdentityLookup 的 Message Filter App Extension。系统只会把未知发送者的 SMS/MMS 查询交给扩展；iMessage、通讯录联系人和系统不再查询的会话不在覆盖范围内。扩展可以用本地规则决定分类，也可以请求系统代为访问关联服务；扩展本身不能直接访问网络或共享容器。

第一版分类：垃圾、营销、诈骗、交易、其他。默认采用保守策略：无法判断时不拦截，并保留用户反馈入口。

### 来电过滤

使用 CallKit Call Directory App Extension。扩展在 `beginRequest(with:)` 中一次性提供号码识别标签和阻止号码，号码必须按升序批量提供。系统不会在每一通来电到达时启动扩展让它实时请求服务，因此数据更新必须由 App 维护目录并请求系统 reload。

第一版能力：号码识别、已知骚扰号码阻止、目录更新时间和失败提示。暂不承诺实时云查号、按来源 App 识别或通话内容分析。

### 广告拦截

保留现有 URL Filter G0/G3 研究记录，但从 V2 产品主线移除。没有 `url-filter-provider` entitlement、官方 Bloom 数据、PIR 服务和真机受控 URL 证据时，不在 UI 中显示已启用广告过滤，也不把 URL Filter extension 作为当前 IPA 的安装前提。

## 四页 UI 结构

| 页面 | V2 重点 |
| --- | --- |
| 概览 | 短信过滤、来电过滤两个状态卡；广告拦截显示“暂缓” |
| 规则 | 短信分类、号码目录来源、更新时间、误报反馈 |
| 诊断 | 扩展启用状态、目录加载结果、短信分类结果和失败原因 |
| 设置 | 系统设置入口、隐私说明、数据源与更新策略、清理本地事件 |

视觉上沿用现有 QingQiDesignSystem：浅绿色提示条、白色圆角卡片、深色模式语义色、原生 TabView、Dynamic Type 和可访问性标签。

## 不承诺

- 过滤 iMessage 或通讯录联系人短信。
- 通过普通 App 读取全部短信历史。
- 每通电话实时联网识别号码。
- 读取通话内容、录音或 TLS 流量。
- 在没有系统扩展和用户授权时用 UI 状态伪造“已拦截”。
